## Round 3: Cross-Platform Lock Import Blocker

Finding: round 2 added a top-level `import fcntl` to the shared
`lib/provider_backends/codex/runtime_artifacts.py`; a Windows runtime
importing that module fails with ModuleNotFoundError.

Fix: `GenerationLock` now delegates to the existing cross-platform
`provider_core.runtime_lock.ProviderLock` (review-proven POSIX/Windows
pattern, per-platform lazy imports inside that module). The shared Codex
modules contain no platform-specific imports of their own; importing
`runtime_artifacts`/`app_server` with `fcntl` removed from the import
surface succeeds. No Windows code was moved into shared or Herdr-owned
paths, and the isolation gate itself is unchanged.

Tests (both in the Windows-owned `test/test_windows_pr_isolation.py` so the
repair diff stays non-Windows-scoped):

- `test_shared_codex_modules_import_without_fcntl`: both shared modules
  import and expose their API when `fcntl` raises ModuleNotFoundError
  (pre-fix: collection error on the old top-level import).
- `test_generation_lock_mutex_semantics_via_msvcrt_simulation`: with a
  fcntl-backed msvcrt simulation and `is_windows()` forced true, the lock
  stays exclusive (contender cannot acquire) and reacquirable after release.

Isolation note: the two simulation tests contain Windows markers by design;
per the frozen gate policy they must ship in the Windows-owned test file
and be committed separately from the shared-repair diff (gate semantics:
any diff-marker in a mixed diff marks it Windows-scoped and blocks the
protected paths). The gate result for the repair diff itself, with the
Windows-owned test file excluded, is **pass scope=non-windows** (simulated
via the checker API with the identical inputs; the worktree cumulative
diff including the test file intentionally fails the gate and must be split
at publication time by agent1).

## Round 2: Agent1 Review Repairs

All review findings were reproduced first, then fixed, then re-verified:

### P1-1: shutdown cleanup deleted a live successor's PID and marker

Reproduction (script `/var/tmp/ccb-repair-lEOL/repro_round2.py`): synthetic
live successor (pid=os.getpid() + generation JSON + live bound socket) ->
`cleanup_codex_app_server_shutdown_artifacts` deleted pid+marker while the
socket stayed bound (orphan). Pre-fix: `P1-1` failures reported. Fix: the
whole artifact set is owner-checked before any unlink; a live owner keeps
all three. New tests:
`test_shutdown_cleanup_preserves_live_successor_artifact_set` (pre-fix
failed), `test_shutdown_cleanup_removes_dead_owner_artifacts` (control).

### P1-2: _restore_pid_record overwrote a live successor record

Reproduction: live record (os.getpid) + older dead snapshot -> restore
overwrote the live record. Fix: restore only when the current record's
owner is dead or unchanged; a live foreign owner is never overwritten.
Tests: `test_failed_start_restore_never_overwrites_live_successor_record`
(pre-fix failed), `test_failed_start_restore_overwrites_dead_foreign_record`
(control).

### P1-3: no serialized claim; concurrent first starts

Fix: `GenerationLock` (fcntl.flock on `runtime_dir/app-server.lock`, shared
by `app_server.py` and `runtime_artifacts.py`) serializes the whole claim
protocol of start() and the cleanup of stop()/shutdown. Bounded acquisition
(5s) fails fast to the local-fallback path; no unbounded retry or duplicate
task submission. Tests: `test_concurrent_first_starts_yield_exactly_one_claim`
(two threads, exactly one winner, loser does not destroy winner's artifacts;
pre-fix failed - both could observe a fresh socket+live child).

### P1-3b: pane-level stale socket attachment

Reproduction (script `/var/tmp/ccb-repair-lEOL/repro_pane.py`, driving the
REAL generated pane command with a fake codex shim): pre-fix X1 failed -
the pane's `-S` wait attached to a dead leftover node. Fix: the pane script
stamps a wait-reference file before the first check and requires the socket
node to be newer (`find <socket> -newer <ref>`); a node created before the
pane started can never satisfy the wait. A socket bound by the owning
generation after the pane started still takes the remote branch; when `find`
is unavailable the plain `-S` check applies and the real `codex --remote`
connect remains the final arbiter. Tests:
`test_managed_pane_command_ignores_stale_socket_node` (pre-fix failed),
`test_managed_pane_command_attaches_when_socket_appears_after_start`
(control).

Note: a socket bound *before* the pane started (old generation still alive
during overlap) no longer satisfies the pane wait; the pane falls back to the
local CLI for that launch instead of attaching to an endpoint that is about
to be replaced. The next pane launch attaches to the new generation. This
is the intended crash-loop avoidance.

### P2-4: remote-resume override detection missed flag forms

Reproduction: `--sandbox=read-only`, `--ask-for-approval=never`, `-s`,
`-a`, `--dangerously-bypass-approvals-and-sandbox`, `--approve-for-me`,
`-c sandbox_mode=...`, `-c approval_policy=...` were all missed. Fix:
`_codex_permission_overrides_present` tokenizes with arity-aware handling of
attached values, short aliases, standalone switches, and permission config
keys; option values are never treated as subcommands; non-permission config
(`-c model=...`) does not block. The permission policy is never stripped:
blocked resumes run on the local CLI. Parametrized test
`test_remote_resume_blocked_by_permission_overrides_spellings` (20 cases,
pre-fix failed on 5+ spellings).

CLI verification limitation: the installed codex CLI exits with
"stdin is not a terminal" before flag validation in this headless
environment, so the exact remote-resume rejection could not be re-probed
live; the flag surface was taken from `codex --help` (verified: `-s`,
`-a`, `--dangerously-bypass-*`, `--approve-for-me`) and from the issue
reports. The detector errs toward treating permission forms as blocking
(conservative: local resume keeps the policy effective).

### P2-5: render_clear hid the confirmation scope

Fix: `render_clear` appends `confirmed=input_delivered` for cleared results.
Tests: `test_render_clear_includes_agent_results_and_confirmation_scope`
(pre-fix failed),
`test_render_clear_without_confirmed_field_keeps_existing_shape` (control).

### P2-6: short-socket test hardcoded /tmp

Fix: `test_managed_app_server_uses_owned_short_socket_for_long_runtime_path`
now derives a short writable root under the process tempdir
(`tempfile.gettempdir()/ccb-t<pid>`) instead of hardcoding `XDG_RUNTIME_DIR=/tmp`;
the long-path-shortening assertions are unchanged. The test now runs and
passes on this /tmp-inode-exhausted host (previously deselected). No other
/tmp data touched.

## Per-Issue Results

### #345 (app-server generation race)

Reproduced deterministically with real Unix sockets and fake listener
children driven through the real `ManagedCodexAppServer` supervisors
(script preserved at `/var/tmp/ccb-repair-lEOL/repro_345.py`). Pre-fix
failure modes reproduced:

- F1 blind unlink of a live foreign socket (pane ENOENT during overlap);
- F2 `is_socket()`-only readiness let a bind-failing child report ready;
- F3 old generation's stop removed a newer generation's socket;
- F4 a failed start clobbered the PID registry enabling F3.

Post-fix: X1 foreign endpoint stays connectable during overlap; X2
bind-failing child reports `start() == False`; X3 after old exit the new
generation starts and owns the endpoint; X4 old stop never removes the new
generation's socket. `FIXED: all generation-fencing expectations hold`
(x5 consecutive runs; x3 further runs). Pre-fix run of the same script
reported `RACE STILL PRESENT` with X2/X3/X4 violations.

Pytest: `test_codex_app_server_followup.py` — pre-fix: new overlap and
fencing tests failed (2 of the added tests failed pre-fix: dead-pane-era
expectations); post-fix: 17 passed, 1 deselected.

### #346 (remote resume + honest clear)

Resume: pre-fix build produced
`codex --remote <sock> --ask-for-approval never --sandbox danger-full-access --dangerously-bypass-hook-trust resume <id>`
(the exact CLI rejection shape). Post-fix the same launch builds a local
`resume` with all three override flags intact; remote remains for fresh
starts and for resumes without overrides (controls verified).
Clear: dead pane reports `failed/pane_dead` (pre-fix reported `ok/cleared`);
pane dying mid-sequence reports `failed/pane_dead_after_input`; transport
failure reports `failed`; CLI exits 1 on failed clear (pre-fix exited 0).
`cleared` now carries `confirmed: input_delivered` to distinguish input
delivery from a provider-native confirmed context reset.

### #347 (task_complete.error ignored)

Pre-fix: synthetic sequence (assistant progress, then the issue's exact
`task_complete.error` shape with `last_agent_message: null`) ended as
`turn_boundary` and the detector reported `COMPLETED` (or
`INCOMPLETE/task_complete_empty_reply` when no progress existed) — the
error was dropped. Post-fix: Python and Rust paths emit
`turn_aborted {reason: task_complete_error, status: failed,
provider_error_category: misalignment_policy_violation, error_message,
error_type}`; the integrated test (raw event → normalization → state
machine → ProtocolTurnDetector) asserts `FAILED`,
`reason=task_complete_error`, preserved category, and the earlier progress
text remaining only as failure context. Generic errors without a category
also fail. Genuine successful `task_complete` and empty completions keep
their existing behavior (controls). No retry/model-switch/resubmit logic
was added anywhere.

### #348 (Kimi timeout knob filtered)

Pre-fix: `control_plane_env()` dropped `CCB_KIMI_NATIVE_TURN_TIMEOUT_S`
(regression test failed with KeyError pre-fix). Post-fix: the variable is
preserved through `control_plane_env()`; the Kimi adapter test proves a
301s poll is inside a configured 900s budget (no terminal decision) and a
901s poll expires with `kimi_native_turn_timeout` and
`max_wait_secs == 900.0`; an invalid value falls back to the 300s default.
Default policy unchanged; the default 300s cap is not altered. Tool-based
activity extension remains deferred (out of scope, per plan).
