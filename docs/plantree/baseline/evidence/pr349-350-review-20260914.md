## PR349

Head: `719fc9ee3fd5eb3bc3a35637112a91bf9064d2c1`.

- Blocking authority issue: `_ensure_managed_private_keychain` includes the
  external login database in the managed search list. Search-list membership
  is not a read-only permission. Choosing a private default does not prevent
  updates/deletes of matching items in the external database.
- Private database and Preferences ancestors are not validated against aliases
  before security writes. This needs the same ownership checks as other
  credential destinations.
- Trusted-main Windows isolation gate fails on `windows-platform-check`.
  This is the known Darwin `platform.system()` classifier false positive,
  not evidence of new Windows dependencies. Do not bypass the gate.
- GitHub reports failed required tests and isolation checks at this head.
- Local Provider-profile and source-runtime-guard suites: **190 passed** after
  supplying pytest, cryptography, and aiohttp in an isolated uv environment.
  Passing local focused tests does not clear the authority or CI blockers.

## PR350

Head: `e28250d1e956c2cea283f828986e95ebefaf8804`.

- Independent private Keychain direction is preferable to PR349's search list.
- Blocking upgrade bug: old auth manifests do not contain `projected_json_keys`.
  `_materialize_auth` interprets this as no owned account metadata, while
  `_projected_claude_json_payload` now preserves metadata in independent mode.
  Switching an existing installation to `inherit_auth=false` therefore retains
  inherited `oauthAccount` as if it belonged to the independent login. This
  affects Linux too; it is not a macOS-only change.
- Reproduced using a synthetic source account, materializing inherited state,
  removing the new manifest field to represent the old schema, and switching
  to independent mode. Assertion that inherited `oauthAccount` is absent fails.
  No real credentials or provider endpoints were used.
- Existing four focused suites: **359 passed**. Additional upgrade regression:
  **1 failed**. Trusted-main isolation gate: **pass scope=non-windows**.
- PR description explicitly lacks real Keychain creation acceptance. Mocked
  commands do not establish native default/search-list or login/logout isolation.

## Disposition

Neither PR is safe to merge unchanged. Prefer repairing PR350 with explicit
old-manifest migration and native macOS qualification; do not combine the two
competing Keychain implementations. PR349's generic source-guard wording can
be reviewed independently. Main and remote PR state were left unchanged.

Tests initially hit exhausted `/tmp` inodes; reruns use an isolated directory
under `/var/tmp`. This environmental failure is not attributed to either PR.
