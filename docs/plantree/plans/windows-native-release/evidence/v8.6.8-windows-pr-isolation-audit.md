# v8.6.8 Windows PR Isolation Audit

Date: 2026-08-17
Status: corrective rollback and isolation gate landed locally in
`7d74e92a8` and `23d62228f`; strict native-only hardening landed in
`702870c1b`

## Authority and scope

The accepted boundary places Windows runtime code under
`lib/platforms/windows/` and Windows release tooling under
`platforms/windows/`. Shared Linux/macOS release builders and npm ownership
must remain unchanged.

The audit covers the four Windows/Herdr feature commits added after `v8.6.7`.
It does not roll back Mobile work, release identity/history, the Windows-only
newline filename skip, or unrelated test-mock corrections.

## Unknown Agent symptom

`Toolbarfix` and `Toolbarcoder` are not literals in the tracked source at
`v8.6.8`. The code supports this likely chain:

1. `0eb15c4b1` releases CCB pane-agent authority to Herdr native detection at
   launch/respawn time.
2. Herdr-derived pane/process metadata can then surface names not declared in
   CCB config.
3. `67a95fea1` can retain removed or stale Agent directories when runtime
   state is not `STOPPED`, even after recorded PIDs are dead.

This explains how unknown names can appear and persist, but the exact producer
cannot be proven without lifecycle/overlay evidence from the affected Windows
host. The rollback removes both newly introduced paths.

## Corrective change

Exact reverse patches were applied, newest first, for:

- `67a95fea1`
- `f87f995ff`
- `0eb15c4b1`
- `92dae890d`

All 18 affected files match the corresponding pre-change parent content. The
rollback is committed locally as `7d74e92a8`; it has not been pushed or
published.

The new checker at
`platforms/windows/tools/check_pr_isolation.py` evaluates the PR merge-base to
head diff, including commit subjects and added/removed Windows markers. The
dedicated `.github/workflows/windows-pr-isolation.yml` workflow runs it for
every PR and landed in `23d62228f`. The checker also freezes 24 existing
reverse-import edges across 16 shared files and permits only edge removal.

The strict-gate hardening in `702870c1b` removes global README, release-note,
`CHANGELOG.md`, and `VERSION` exceptions; recognizes Windows API/platform
markers and `from platforms import windows`; rejects symlink traversal during
the dependency scan; and runs the policy checker from the trusted base
revision. The workflow treats the PR checkout as data and uses
`pull_request_target` with read-only permissions.

## Residual risk and landing order

- Real macOS execution was not available locally. Existing required CI has a
  macOS Python 3.11 full-suite lane and a separate macOS install smoke; both
  must pass before acceptance.
- Real Windows/Herdr reproduction was not available locally. The Windows
  support tier remains beta.
- The 16 historical shared importers of Windows modules are bounded but not
  yet eliminated; full physical isolation requires a separate facade/lazy-load
  refactor.
- The corrective rollback and checker/workflow are landed locally in that
  order. Make the new workflow a required PR check after branch protection is
  updated.
