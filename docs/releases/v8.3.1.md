# CCB v8.3.1

Released: 2026-07-24

## English

### Highlights

- Provider upgrades are now coordinated by `ccb update`. Managed panes suppress
  supported provider-native startup prompts, while CCB detects executable
  ownership, compares exact versions, and lets you update, decline, or skip
  only the detected version. Active provider panes are never restarted
  automatically.
- Project-scoped Claude and Gemini software caches are retired from the runtime
  path. Claude uses the user-installed executable, and Gemini uses one
  user-scoped rebuildable cache instead of duplicating provider software in
  every project.
- Config UI access can use a persistent loopback port and a token source from
  `token_env` or a protected project-relative `token_file`. Token values remain
  out of project configuration and CLI output.
- Qoder CLI CN is available as the `qodercn` provider for the official
  `@qodercn-ai/qoderclicn` distribution. Its visible pane and headless asks
  share isolated config/session state, and completion requires a successful
  native terminal result.

### Reliability and usability

- After a CCB update, the newly installed version performs bounded legacy-cache
  cleanup. Only ownership-verified, manifest-valid Claude/Gemini cache payloads
  are eligible; active projects, unknown content, foreign links, sessions,
  authentication data, and user-scoped caches are preserved. Deferred caches
  are reconsidered after the owning project next shuts down successfully.
- Accepted shutdown work keeps its finalization path while the server is
  stopping, preventing cleanup callbacks from being abandoned.
- `ccb kill` now completes authoritative local cleanup when the keeper closes
  the control-plane socket immediately after shutdown intent is recorded,
  instead of exposing a transient `No such file or directory` error.
- WSL process-resource audits keep live processes visible when per-process
  procfs I/O counters are unavailable, reporting partial I/O capability instead
  of incorrectly treating those processes as gone.
- Qoder and Qoder CLI CN now use their native `--print`, workspace,
  `--config-dir`, permission, UUID session, and stream-result contracts.
  Managed Qoder CLI CN settings suppress its own update prompts without
  changing the user's global configuration.
- Rich mode now uses a compact two-column Yazi layout, giving more space to the
  file list and active preview.
- Sidebar release checksum generation is portable across supported build hosts.

### Upgrade notes

- No manual data migration is required. `ccb update` performs the safe legacy
  cache migration after a version change; use `ccb update --no-cache-cleanup`
  to opt out for one update.
- Provider updates remain user-controlled. Use `--providers check`,
  `--providers all`, or `--providers none` for report-only, supported
  non-interactive updates, or an explicit skip.
- npm-managed installations can run
  `npm install -g @seemseam/ccb@8.3.1`.
- Linux, macOS, npm, and Android versions, download metadata, and checksums are
  synchronized to this release.

## 中文

### 主要更新

- Provider 升级现在统一由 `ccb update` 管理。托管 pane 会关闭受支持的
  Provider 原生启动更新提示；CCB 会识别可执行文件归属、比较准确版本，并允许
  用户选择更新、暂不更新，或只跳过当前检测到的版本。该流程不会自动重启正在
  运行的 Provider pane。
- 项目级 Claude 与 Gemini 软件缓存已经退出运行路径。Claude 直接使用用户安装
  的可执行文件，Gemini 使用一份用户级、可重建的缓存，不再为每个项目重复复制
  Provider 软件。
- Config UI 现在可使用固定的 loopback 端口，并从 `token_env` 或受保护的项目内
  相对 `token_file` 读取 token。token 值不会写入项目配置，也不会显示在 CLI
  输出中。
- 新增 `qodercn` Provider，支持官方
  `@qodercn-ai/qoderclicn` 发行版。可见 pane 与非交互 ask 共用隔离的配置和
  session 状态，并且只有 Provider 原生的成功终态 result 才会完成任务。

### 可靠性与易用性

- CCB 更新完成后，新版本会执行有边界的旧缓存清理。只有归属可验证且 manifest
  有效的 Claude/Gemini 缓存 payload 才可能被删除；运行中的项目、未知内容、
  外来链接、session、认证数据和用户级缓存都会保留。暂缓清理的缓存会在所属
  项目下一次成功关闭后重新判断。
- 服务进入 stopping 状态后，已经接受的 shutdown 工作仍会完成 finalizer，
  避免清理回调被提前丢弃。
- shutdown intent 写入后，即使 keeper 立即关闭控制面 socket，`ccb kill` 也会
  继续完成本地权威清理，不再向用户暴露短暂的 `No such file or directory`
  错误。
- WSL 缺少单个进程的 procfs I/O 计数时，进程资源审计仍会保留已发现的存活
  进程，并明确报告 I/O 能力不完整，不再将其误判为进程已经退出。
- Qoder 与 Qoder CLI CN 现在遵循各自原生的 `--print`、工作目录、
  `--config-dir`、权限、UUID session 和流式 result 协议。托管的 Qoder CLI
  CN 配置会关闭其自身更新提示，同时不修改用户的全局配置。
- Rich 模式改为更紧凑的 Yazi 双栏布局，为文件列表和当前预览留出更多空间。
- Sidebar 发布包的校验和生成方式已兼容受支持的不同构建主机。

### 升级说明

- 本次升级不需要手工迁移数据。版本更新后，`ccb update` 会执行安全的旧缓存
  迁移；如需单次跳过，可使用 `ccb update --no-cache-cleanup`。
- Provider 更新仍由用户决定。可使用 `--providers check`、
  `--providers all` 或 `--providers none` 分别执行仅检查、受支持的非交互
  更新或明确跳过。
- 由 npm 管理的安装可执行
  `npm install -g @seemseam/ccb@8.3.1`。
- Linux、macOS、npm 与 Android 的版本、下载元数据和校验和均已同步到本次
  发布。
