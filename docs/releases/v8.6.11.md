# v8.6.11

Released: 2026-08-27

## English

### Highlights

- Managed Codex CLI `0.149.0` custom providers now declare the Agent-local
  `OPENAI_API_KEY` environment source when an explicit key is configured, so
  requests carry the expected bearer token instead of failing with `401
  Unauthorized`. Route-only local gateways continue to omit authentication.
- Codex Agents can project an explicit `model_catalog_json`, and an Agent model
  now overrides the inherited global model without changing other Agents.

### Fixes and reliability

- Herdr pane state now follows CCB lifecycle transitions with monotonic
  reporting through an optional terminal capability implemented inside the
  Windows backend. Shared runtime code does not import Herdr or other Windows
  implementation modules (PR #320).
- Native Windows launchers enable Python UTF-8 mode for CCB and its child
  processes without changing shared Linux/macOS subprocess call sites
  (PR #323). Windows x64 and Herdr remain beta.
- Managed Codex reconnect startup and tmux history policy are preserved after
  restart (PR #321). The keeper now inherits `CCB_TMUX_CONFIG`, retaining an
  explicitly selected tmux configuration (PR #326).
- Pi clear uses `/new` to start a fresh native context (PR #325). Codex model
  catalog and per-Agent model support comes from PR #322.

### Upgrade notes

- Restart managed Codex Agents after upgrading so their private config is
  regenerated with the corrected custom-provider authentication fields.
- Restart active CCB projects to apply the keeper environment and terminal
  lifecycle changes. No project, conversation, pairing, or configuration
  migration is required.

### Known limitations

- Native Windows x64 and Herdr remain beta. Their artifact build, archive
  install, launcher smoke, and contract tests are owned by the Windows release
  workflow; real user GUI/provider qualification remains separate.

## 中文

### 版本亮点

- 显式配置 API key 时，受管 Codex CLI `0.149.0` 自定义 provider 现在会声明
  Agent 本地 `OPENAI_API_KEY` 环境来源，使请求携带预期 bearer token，不再返回
  `401 Unauthorized`。只有 route 的本地 gateway 仍不启用认证。
- Codex Agent 可以投影显式 `model_catalog_json`，且 Agent 自身 model 会覆盖继承
  的全局 model，不影响其他 Agent。

### 修复与稳定性

- Herdr pane 状态现在通过 Windows backend 内实现的可选 terminal 能力，按 CCB
  生命周期单调更新。共享运行时代码不会 import Herdr 或其他 Windows 实现模块
  （PR #320）。
- 原生 Windows launcher 为 CCB 及其子进程启用 Python UTF-8 模式，不修改共享
  Linux/macOS subprocess 调用点（PR #323）。Windows x64 与 Herdr 仍处于 beta。
- 受管 Codex 重启后会保留 reconnect 启动和 tmux history 策略（PR #321）。
  keeper 现在会继承 `CCB_TMUX_CONFIG`，保留用户显式选择的 tmux 配置
  （PR #326）。
- Pi clear 改用 `/new` 创建新的 native context（PR #325）。Codex model catalog
  和按 Agent model 支持来自 PR #322。

### 升级说明

- 升级后请重启受管 Codex Agent，使其私有配置使用修正后的自定义 provider
  认证字段重新生成。
- 请重启活跃 CCB 项目，以应用 keeper 环境和 terminal 生命周期变更。无需迁移
  项目、对话、配对或配置。

### 已知限制

- 原生 Windows x64 与 Herdr 仍处于 beta。artifact 构建、archive 安装、launcher
  smoke 和合同测试由 Windows 发布工作流负责；真实用户 GUI/provider 验证仍需
  单独完成。
