# v8.6.14

Released: 2026-09-06

## English

### Highlights

- This is the first public package and artifact release built from the merged
  `main` line containing PRs #320, #321, #322, #323, #325, #326, #328, #329,
  #330, #331, #332, #333, #334, #335, #336, #337, and #339.
- Config UI now supports direct pane drag, edge placement, center swapping,
  split resizing, undo, and serialization back to the existing V2 layout
  syntax. It also offers Pi local-model selection, Codex Astra models, and Pi
  thinking-level controls.
- CCB Mobile can aggregate projects from multiple paired hosts, group them by
  computer, and persist custom host display names.

### Fixes and reliability

- Herdr lifecycle state now follows live CCB runtime transitions instead of
  freezing at `unknown` (#320). Codex reconnect uses the supported wrapper,
  tmux history has a configurable lower default (#321), and per-Agent Codex
  `model_catalog_json` plus model overrides reach managed homes (#322).
- Windows subprocess output is handled as UTF-8 (#323). Fork PR checkout and
  the existing Herdr lifecycle edge are covered by the trusted Windows
  isolation policy (#331, #336), without adding a Windows-only dependency to
  the shared Linux/macOS runtime.
- Pi clear now starts a native new context with `/new` (#325), custom tmux
  configuration survives the managed control plane (#326), and Pi profile
  assets use shared immutable snapshots with complete offline dependency
  closure (#328, #334).
- Accepted `ask` submissions now explicitly return the Agent turn to CCB
  (#329), and managed Provider homes preserve the user's Git author and
  committer identity (#330).
- Pi, OMP, and OpenCode processes can share Magic Context storage through a
  validated `MAGIC_CONTEXT_STORAGE_DIR` (#332). Mobile multi-host support is
  delivered by #333; Config UI pane editing, Pi model selection, and
  Codex/Pi thinking controls are delivered by #335, #337, and #339.
- The visible OMP ask/native-completion behavior, multi-tool terminalization,
  public Provider-priority documentation, and Config V1/V2 role filtering
  prepared for v8.6.13 are included in this `main`-based build.

### Upgrade notes

- Restart managed Codex, Pi, and OMP Agents and restart CCB projects after
  upgrading so managed homes, environment projection, reconnect behavior, and
  Config UI capabilities are refreshed.
- Upgrade both the CCB host and CCB Mobile APK to use multi-host grouping and
  host display names. Saved pairings remain compatible.
- Config UI layout edits continue to use the existing V2 syntax; applying a
  changed layout still requires a project restart.
- No project, conversation, pairing, or configuration migration is required.

### Known limitations

- Native Windows x64 and Herdr remain beta. Windows release artifacts and
  isolation gates remain owned by the separate Windows workflow.
- Pi custom Astra entries need `reasoning: true` and an explicit
  `thinkingLevelMap`. A valid older Codex model cache remains authoritative
  until its catalog is refreshed and Config UI is restarted.

## 中文

### 版本亮点

- 这是首次从已合并的 `main` 主线构建公开 npm 包和平台产物，正式包含 PR
  #320、#321、#322、#323、#325、#326、#328、#329、#330、#331、#332、
  #333、#334、#335、#336、#337 和 #339。
- Config UI 现在支持直接拖动 pane、边缘放置、中心换位、调整分割比例、撤销，
  并将结果写回现有 V2 layout 语法；同时加入 Pi 本地模型选择、Codex Astra
  模型和 Pi 思考强度控制。
- CCB Mobile 现在可以聚合多台已配对主机的项目、按电脑分组，并持久化自定义
  主机显示名称。

### 修复与稳定性

- Herdr 生命周期状态现在会跟随 CCB runtime 实时变化，不再冻结在 `unknown`
  (#320)。Codex reconnect 改用受支持的 wrapper，tmux history 使用可配置的较低
  默认值 (#321)，每个 Agent 的 Codex `model_catalog_json` 和模型覆盖也会进入
  受管 home (#322)。
- Windows subprocess 输出统一按 UTF-8 处理 (#323)。可信 Windows 隔离策略现在
  覆盖 fork PR checkout 和既有 Herdr lifecycle 边 (#331、#336)，且不会向
  Linux/macOS 共享运行时加入 Windows 专属依赖。
- Pi clear 现在通过 `/new` 启动原生新上下文 (#325)，自定义 tmux 配置可以穿过
  受管控制平面 (#326)，Pi profile assets 使用共享不可变快照并保留完整的离线
  依赖闭包 (#328、#334)。
- `ask` 提交被接受后会明确把 Agent turn 交还 CCB (#329)，受管 Provider home
  会保留用户的 Git author 和 committer identity (#330)。
- Pi、OMP 和 OpenCode 进程可通过经过校验的 `MAGIC_CONTEXT_STORAGE_DIR` 共享
  Magic Context 存储 (#332)。移动端多主机支持由 #333 交付；Config UI pane
  编辑、Pi 模型选择和 Codex/Pi 思考强度控制分别由 #335、#337 和 #339 交付。
- 为 v8.6.13 准备的可见 OMP ask/原生 completion、多工具终止判定、公开 Provider
  优先级文档和 Config V1/V2 角色过滤修复，均已进入这个基于 `main` 的构建。

### 升级说明

- 升级后请重启受管 Codex、Pi 和 OMP Agent，并重启 CCB 项目，以刷新受管 home、
  环境投影、reconnect 行为和 Config UI 能力。
- 如需使用多主机分组和主机显示名称，请同时升级 CCB host 与 CCB Mobile APK；
  已保存的配对仍然兼容。
- Config UI 布局编辑继续使用现有 V2 语法；应用修改后的布局仍需重启项目。
- 无需迁移项目、对话、配对或配置。

### 已知限制

- 原生 Windows x64 与 Herdr 仍处于 beta；Windows 发布产物和隔离门禁继续由独立
  Windows workflow 负责。
- Pi 自定义 Astra 条目需要 `reasoning: true` 和显式 `thinkingLevelMap`。有效的
  Codex 旧模型缓存仍保持权威，需刷新目录并重启 Config UI 后才会更新。
