# v8.6.17

Released: 2026-09-14

## English

### Fixes and reliability

- Codex provider safety and terminal errors now remain failed results with the
  provider error category preserved; earlier progress text is never promoted
  to a successful handback (#347).
- Remote Codex resume avoids unsupported permission override combinations while
  preserving the requested policy. `ccb clear` reports dead panes and
  distinguishes input delivery from provider-native reset confirmation (#346).
- Codex app-server startup and shutdown now fence generations, verify a live
  connected endpoint, and protect socket/PID/marker ownership during restart
  races (#345).
- `CCB_KIMI_NATIVE_TURN_TIMEOUT_S` now reaches the daemon control-plane
  environment. The default 300-second timeout remains unchanged (#348).

### Upgrade notes

- Upgrade the CCB host and Mobile APK to v8.6.17, then restart managed CCB
  services. No manual project, pairing, or Provider-auth migration is required.
- Provider authentication remains one-way inherited state: log in through the
  Provider's normal CLI, then restart CCB to inherit it. CCB does not reverse
  manage Provider credentials or configuration.

### Known limitations

- Native macOS app-server qualification was unavailable during this release
  preparation; Linux Unix-socket lifecycle tests cover the repaired race.
- Windows remains beta and stays isolated from shared Linux/macOS runtime code.

## 中文

### 修复与稳定性

- Codex Provider 的安全阻断和终止错误现在始终以失败结果返回，并保留
  Provider 错误类别；不会把早期进度文字提升为成功 handback（#347）。
- 远程 Codex resume 避免使用不兼容的权限覆盖组合，同时保留请求的权限
  策略。`ccb clear` 会报告 pane 已死亡，并区分“输入已送达”和 Provider
  原生确认重置（#346）。
- Codex app-server 启动和关闭现在隔离不同代际，验证端点可连接，并在重启
  竞态期间保护 socket、PID 和 marker 的所有权（#345）。
- `CCB_KIMI_NATIVE_TURN_TIMEOUT_S` 现在可以传递到 daemon 控制平面；默认
  300 秒超时策略保持不变（#348）。

### 升级说明

- 请将 CCB 主机和 Mobile APK 升级到 v8.6.17，然后重启托管 CCB 服务。无需
  手动迁移项目、配对或 Provider 认证。
- Provider 认证继续采用单向继承：先通过 Provider 官方 CLI 正常登录，再
  重启 CCB 继承登录状态。CCB 不会反向管理 Provider 凭据或配置。

### 已知限制

- 发布准备期间无法进行 macOS 原生 app-server 验证；Linux Unix socket
  生命周期测试覆盖了本次修复的竞态机制。
- Windows 仍处于 beta，并继续与共享 Linux/macOS 运行时代码隔离。
