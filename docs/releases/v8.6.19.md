# v8.6.19

Released: 2026-09-19

## English

### Highlights

- Requests and returned results share one chronological queue per agent.
  A returned result holds its execution slot until the receiving provider's
  processing turn ends, preventing later messages from interrupting that turn.
  Both message types reuse existing provider completion evidence.
- Added `ccb screen <agent>` for read-only tmux text capture. Use `--lines 120`
  for scrollback context or `--json` for structured output. CCB validates pane
  ownership and rejects missing, dead, or changed bindings without sending keys,
  changing focus, starting a daemon, or substituting old logs.

### Fixes and reliability

- Empty and abnormal ask replies provide English inspection guidance: inspect
  the target screen, correlate the original job with `ccb trace`, and decide
  whether to wait, retrieve a result, continue, safely resend, or pause.
  Empty provider results no longer trigger automatic retries; original error
  details, cancellation, successful silence, and chain handoff semantics remain.
  Existing explicit API/runtime retry policies are unchanged.
- OMP relaunch and pane recovery resume the exact observed native conversation
  using validated session identity and `--resume`. Explicit session selection
  and disabled restoration remain authoritative. Missing or invalid evidence
  produces an explicit fresh-session reason instead of choosing by file age.
  External provider configuration and credentials remain untouched.

### Upgrade notes and limitations

- Upgrade to `v8.6.19` and restart managed runtimes when idle to activate the
  new dispatcher and prompt behavior. No manual state migration is required.
- Real Codex/OMP queue ordering and screen capture were verified, as was native
  OMP conversation loading. Real OMP empty-terminal and Claude queue qualification
  remain open; OMP may continue internally after an empty model response.
- Screen capture requires a mounted tmux project and reflects its current pane,
  which may show a later task. It is diagnostic evidence, not a job transcript.
  Previously lost OMP bindings are not reconstructed by guessing. Windows
  remains beta; this release adds no native Windows screen-capture support.

## 中文

### 版本亮点

- 请求和返回结果在每个 agent 上共用按时间排序的队列。返回结果会占用执行槽，
  直到接收方 provider 的处理回合结束，避免后续消息打断当前处理；两类消息
  复用现有 provider 回合结束证据。
- 新增 `ccb screen <agent>`，只读抓取 tmux 文字屏幕；`--lines 120` 补充历史
  上下文，`--json` 输出结构化结果。CCB 校验 pane 归属，拒绝缺失、死亡或已
  变更的绑定，不发送按键、不切换焦点、不启动 daemon，也不以旧日志代替抓屏。

### 修复与稳定性

- 空回复和异常 ask 回复统一注入英文查询提示：先查看目标屏幕，再用 `ccb trace`
  核对原任务，由 caller 判断等待、取结果、继续、安全重发或暂停。空 provider
  结果不再自动重试；保留原始错误、取消、成功静默及链式交接语义。现有明确
  API/运行时错误的重试策略保持不变。
- OMP 重启和 pane 恢复通过校验后的会话身份及 `--resume` 恢复已观察到的准确
  原生对话。尊重显式会话选择和禁用恢复设置；证据缺失或无效时记录明确的新建
  会话原因，不按文件新旧猜测。外部 provider 配置和凭据保持不变。

### 升级说明与限制

- 升级到 `v8.6.19`，在空闲时重启 managed runtime，以启用新调度和提示行为；
  无需手动迁移状态。
- 已验证真实 Codex/OMP 队列顺序、抓屏及 OMP 原生对话加载。真实 OMP 空终局和
  Claude 队列验收仍未完成；OMP 可能在模型空输出后继续内部处理。
- 抓屏要求项目已经挂载 tmux，当前画面可能属于后续任务，只能作为诊断证据，
  不能替代任务记录。不会猜测重建此前丢失的 OMP 绑定。Windows 保持 beta；
  本版未增加原生 Windows 抓屏支持。
