# v8.7.0

Prepared: 2026-09-21

## English

### Highlights

- Human / agent queue mode protects the input composer while a user drafts a
  message. Once the target's current turn ends, only the eligible queue head
  checks input: empty allows delivery; nonempty waits up to 180 seconds. If the
  draft remains, CCB clears it once, confirms empty input, and then delivers.
  Continuing to type does not reset the timer; drafts are not kept indefinitely.
- Agent / agent queue mode retains the chronological request/result FIFO from
  `v8.6.19`. Both `ask` and `back` wait for the preceding message's full processing
  turn to end. Different target agents can still execute concurrently.
- We recommend testing these modes with **Claude, Codex and OMP** in managed
  tmux panes. Input protection for other providers will follow in later updates;
  unsupported transports and older OMP mounts retain unprotected delivery.

### Fixes and reliability

- Historical `esc to interrupt` text and draft words such as `Select Model` or
  `NORMAL` no longer falsely block delivery. Claude's busy animation is detected
  even without an interrupt hint, and its native queued-message prompt is not
  treated as an empty idle composer.
- Busy, modal, copy-mode and unknown observations hold delivery without clearing
  input. A failed or unconfirmed clear is not automatically repeated. Unsent
  waits do not consume provider execution timeouts, and restore starts fresh
  input observations. Ambiguous send errors are not automatically repasted.
- Real Codex, Claude and OMP tasks, two actual 180-second campaigns, ask/back FIFO,
  early manual clearing, modal recovery, narrow windows and manually initiated
  tool turns were verified in an isolated installed project. The focused
  regression suite passed 469 tests; full release checks are recorded separately.

### Upgrade notes and limitations

- This is a local 8.7.0 source preparation, not a published release. The existing
  readiness review remains open: Codex/Claude use `Ctrl-C` for deadline clearing,
  which can interrupt a concurrent user-started turn; generic ambiguous-send
  terminalization and OMP bridge security/lifecycle still require review before
  production promotion. Passing tests does not close those design findings.
- Upgrade to v8.7.0 through the installer or package manager used for your current
  installation. Once tasks finish and drafts are saved, stop the project with
  `ccb kill` and start it with `ccb` to load the updated daemon and OMP extension.
  No manual state migration is required. OMP currently needs its default Status
  Band input layout; an existing process does not acquire the extension in place.
- This first version does not back up drafts or make screen-check/paste/Enter
  atomic against simultaneous typing. Custom editor layouts and keybindings are
  not generally qualified. Native Windows input protection is not added.
- In the injected daemon-termination test, OMP and Claude preserved drafts and
  resumed queued work, but Codex's remote app-server session failed to reconnect.
  With that failure, inspect `ccb screen <agent>` and `ccb trace <job_id>`; the
  tested recovery was to cancel the never-sent queued task, restart the agent,
  and resubmit the original task. Automatic Codex recovery across this failure
  is not qualified, and a queued task can block the normal restart command.

## 中文

### 版本亮点

- 人 / Agent 排队模式保护用户正在编辑的输入框。目标当前回合结束后，只有
  可执行的队首消息才检查输入：为空则投递，非空则最多等待 180 秒；到期仍有
  草稿时清空一次，确认输入框为空后再投递。继续键入不会重置计时，不会无限期
  保留草稿。
- Agent / Agent 排队模式延续 v8.6.19 的请求与结果统一时间顺序 FIFO。
  `ask` 和 `back` 都等待前一条消息处理完整个回合后再投递，不同目标 Agent
  仍可并行执行。
- 推荐先在受管 tmux 环境中的 **Claude、Codex 和 OMP** 上测试使用。其他
  provider 的输入保护将在后续更新中适配；未支持的传输方式和旧 OMP 挂载
  保留原有无输入保护的投递行为。

### 修复与稳定性

- 历史输出中的 `esc to interrupt`，以及草稿中的 `Select Model`、`NORMAL`
  等文字不再被误判为界面状态而阻塞投递。Claude 即使没有中断提示，也能识别
  其忙碌动画；原生队列提示不会被误当成空闲空输入框。
- 正在执行、弹窗、复制模式和未知状态会等待，不会清空输入。清空失败或尚未
  确认时不自动重复清空；未发送等待不消耗 provider 执行超时，恢复后重新观察
  输入。发送结果不明时不自动重复粘贴。
- 已在独立安装项目中验证三家的真实模型任务、两轮实际 180 秒等待、ask/back
  FIFO、提前手动清空、弹窗恢复、窄窗口和人工启动的工具回合。相关回归测试
  469 项通过；完整版本检查另有验证记录。

### 升级说明与限制

- 本次为本地 8.7.0 源码准备，尚未公开发布。既有就绪审查仍未关闭：
  Codex/Claude 到期清空使用 `Ctrl-C`，可能中断同时由用户启动的回合；
  通用发送不明终局处理及 OMP 桥接安全性、生命周期仍需在生产推广前审查。
  测试通过不代表这些设计问题已解决。
- 请使用当前安装对应的安装器或包管理器升级到 v8.7.0。任务结束且草稿保存后，
  用 `ccb kill` 停止项目，再用 `ccb` 启动，以加载新版 daemon 和 OMP 扩展。
  无需手动迁移状态。OMP 当前要求默认 Status Band 输入布局，已运行的进程
  不会原地获得新扩展。
- 首版不备份草稿，最终抓屏、粘贴、Enter 与同时发生的人工输入仍非原子互斥。
  自定义编辑布局和按键尚未全面验证。本版不增加原生 Windows 输入保护。
- 人为终止 daemon 的测试中，OMP、Claude 保留了草稿并恢复排队任务，但 Codex
  远程 app-server 会话未能重新连接。遇到该故障，可用 `ccb screen <agent>`
  和 `ccb trace <job_id>` 检查；已验证的恢复方法是取消尚未发送的排队任务、
  重启 Agent，再重新提交原任务。尚不能宣称 Codex 在此故障下自动恢复，排队
  任务也可能阻止普通重启命令。
