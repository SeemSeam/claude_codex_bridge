# v8.7.1

Prepared: 2026-09-21

## English

### Highlights

- Click a local file or press Enter in the Rich file browser to open it with
  the system default application. Click or Enter on a directory navigates
  inside Yazi. Safe and rich profiles share the behavior; mouse opening targets
  the clicked file rather than a previous hover or unrelated selection.
- macOS uses `open`. Linux prefers `gio open`, falling back to `xdg-open` only
  when GIO is absent. WSL detects its kernel or session environment and uses
  `wslview` from `wslu` to open files through Windows associations, including
  mounted-drive and distribution paths. Missing `wslview` produces an error;
  it does not silently fall back to a Linux GUI. WSL interop must be enabled.
- Filenames containing spaces, quotes and shell punctuation remain individual
  arguments. Multiple selected files are supported. Opener failures are not
  automatically retried through a different application.

### Upgrade and validation

- After upgrading CCB, run `ccb update rich`, then reopen the file-browser pane.
  No Agent restart is required for this file-browser change. Generation updates
  CCB-owned profiles only, leaving user Yazi settings and system associations intact.
- Linux native Yazi 26.5.6 mouse/Enter and directory navigation tests passed in
  disposable tmux servers with recording desktop openers. macOS and WSL command
  routing, arguments and failure handling were tested with platform stubs; real
  macOS/WSL GUI launches were not tested. An accepted OS launch request alone
  does not prove a desktop window rendered. SSH does not open on the client PC.
- Version checks now require all README badges, newest embedded release entries and current APK download links
  to match `VERSION`, with a bilingual notes file for that version.

### Release state and inherited limitations

- This is a local source preparation on top of the unpublished local `v8.7.0`
  commit. At preparation time, GitHub's latest Release and npm were `v8.6.19`,
  while the default-branch README badge still showed `v8.6.13`. No public
  publication is claimed. A later publication must synchronize the default
  branch, immutable tag, release notes, artifacts and registry version.
- It includes the human/agent input guard and agent/agent FIFO described in
  `v8.7.0`, retaining its production-readiness findings: Codex/Claude `Ctrl-C`
  clear ownership, ambiguous-send terminalization and OMP bridge review remain
  open. Forced-daemon-stop Codex remote-session recovery remains manual.

## 中文

### 版本亮点

- 在 Rich 文件面板中点击本地文件或按 Enter，使用系统默认应用打开。
  点击目录或在目录上按 Enter，仍在 Yazi 内导航。safe 和 rich 配置行为一致，
  鼠标打开的是点击的文件，不会误用之前悬停或其他选中的文件。
- macOS 使用 `open`；Linux 优先使用 `gio open`，没有 GIO 时才用
  `xdg-open`。WSL 根据内核或会话环境识别，通过 `wslu` 的 `wslview`
  使用 Windows 文件关联打开，路径包括挂载盘和发行版内文件。缺少
  `wslview` 时明确报错，不静默退回 Linux GUI；必须启用 WSL 互操作。
- 文件名中的空格、引号、Shell 特殊字符保持为完整参数，支持多选文件。
  打开失败时不会自动换用另一个应用重试。

### 升级与验证

- 升级 CCB 后运行 `ccb update rich`，再重新打开文件面板。本次文件面板
  修改无需重启 Agent。生成器只更新 CCB 自有配置，不改个人 Yazi 设置或
  系统文件关联。
- 已在独立 tmux 中用真实 Linux Yazi 26.5.6 验证鼠标、Enter 和目录导航，
  桌面打开工具用记录程序替代。macOS、WSL 的命令选择、参数和失败处理
  已用平台桩验证，未在真实 macOS/WSL 桌面验证。系统接受打开请求不等于
  已确认窗口显示；SSH 不会把文件打开到客户端电脑。
- 新增检查要求各语言 README 徽章、最新内嵌版本记录、当前 APK 下载链接与 `VERSION`
  一致，并存在对应版本的中英文说明。

### 发布状态与继承限制

- 本次在尚未公开发布的本地 `v8.7.0` 提交上准备源码。准备时 GitHub 最新
  Release 和 npm 为 `v8.6.19`，默认分支 README 徽章仍为 `v8.6.13`。
  本次不宣称已公开发布；后续发布必须同步默认分支、不可变标签、发布说明、
  构建产物和包版本。
- 包含 `v8.7.0` 的人/Agent 输入保护与 Agent/Agent FIFO，并保留其生产
  就绪审查问题：Codex/Claude 的 `Ctrl-C` 清空所有权、发送不明终局处理及
  OMP 桥接审查仍未关闭；强制停止 daemon 后 Codex 远程会话仍需人工恢复。
