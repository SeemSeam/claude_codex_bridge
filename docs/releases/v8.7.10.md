# v8.7.10

Released: 2026-10-10

## English

### Pi startup and plugin snapshots

- Reuse verified local Pi plugin snapshots before copying files. Unchanged packages still receive content validation, while shared dependencies are copied once per resolved installation instead of once per dependency branch.
- Preserve dependency versions, scoped packages, optional dependencies and cycles with snapshot-internal links. A real MCP SDK/Zod fixture reduced `es-errors` from 88 physical copies to one and loaded successfully in Pi.
- Add opt-in `.ccb-snapshot-exclude`: one literal relative file or directory path per line, with blank lines and `#` comments allowed. For example, `official-backup/` excludes a backup directory. Patterns and negation are not supported; `.gitignore` is not applied automatically, so ignored runtime build outputs remain available.
- Reclaim abandoned staging directories created by the new snapshot builder after an interrupted process, without deleting final snapshots or changing external Provider files.
- Forward `CCB_STARTUP_TRANSACTION_TIMEOUT_S` through the CLI, keeper and daemon environment boundaries. Explicit values now reach the startup policy; the default remains 30 seconds.

### Verification and upgrade notes

- Verified real Pi extension loading, SDK/Zod imports, and cold/warm full startup of two Pi agents with fresh per-run model responses and extension callback evidence. Focused and expanded regression tests cover cache tampering, content changes, shared module identity, interrupted/concurrent builds and timeout propagation.
- Update CCB, then safely reopen affected projects to use the new startup implementation. No conversation migration is required. Existing snapshots remain usable; the new cache layout is populated on the next full startup.
- Legacy temporary directories without ownership evidence are not automatically removed. The original macOS `empty response from ccbd` incident has not been reproduced or proven fixed; this release addresses confirmed snapshot and timeout propagation defects.
- Desktop, npm and mobile version metadata are synchronized. No new mobile interface behavior is included.

## 中文

### Pi 启动与插件快照

- 在复制文件前复用已验证的 Pi 本地插件快照。未变化的包仍执行内容校验；共享依赖按实际安装目录只复制一次，不再沿每条依赖分支重复展开。
- 通过快照内部链接保留依赖版本、作用域包、可选依赖和循环依赖。真实 MCP SDK/Zod 测试插件中的 `es-errors` 从 88 个实体副本减少为 1 个，并成功在 Pi 中加载。
- 新增可选的 `.ccb-snapshot-exclude`：每行填写一个相对文件或目录路径，支持空行和 `#` 注释。例如，`official-backup/` 可排除备份目录。不支持通配模式或否定规则；不会自动应用 `.gitignore`，以保留被 Git 忽略但运行必需的编译产物。
- 进程中断后，新版快照构建器可回收自己遗留的临时目录，不删除最终快照，也不修改外部 Provider 文件。
- 将 `CCB_STARTUP_TRANSACTION_TIMEOUT_S` 传递到 CLI、keeper 和 daemon 后台环境。显式设置现在能够到达启动策略；默认值仍为 30 秒。

### 验证与升级说明

- 已验证真实 Pi 扩展加载、SDK/Zod 导入，以及两个 Pi Agent 的完整冷启动和缓存复用启动；每轮均核对新的模型回复及扩展回调证据。专项和扩展回归覆盖缓存篡改、内容变更、共享模块身份、中断与并发构建、超时参数传递。
- 更新 CCB 后，在可以安全中断工作时重新打开受影响项目，启用新版启动实现。无需迁移对话。已有快照仍可使用；新版缓存布局会在下一次完整启动时建立。
- 缺少所有权证据的旧版临时目录不会自动删除。原始 macOS `empty response from ccbd` 事件尚未复现，也未证明已解决；本版修复已确认的快照和超时参数传递问题。
- 桌面、npm 与手机端版本元数据同步；不包含新的手机界面行为。
