# v8.7.12

Released: 2026-10-19

## English

### Reply delivery and communication status

- Include PR #395 with reviewed follow-up repairs: a reply pending for at least five minutes can recover a proven orphaned delivery lease while retaining its original job and attempt. Recovery no longer creates replacement jobs that remain queued indefinitely.
- Preserve valid lease ownership and execution evidence. Live jobs, pending events and uncertain state reads continue to block automatic intervention; elapsed time alone does not authorize resending a reply.
- Successful silent tasks and callback child tasks show terminal status instead of a permanent reply-queued indicator. Pending reply deliveries appear in the communication list, linked to their source task, and the list retains 20 recent rows.

### Composer compatibility

- Recognize titled Claude input borders and known undimmed Codex placeholders/status layouts. Restore support for trailing spaces on ordinary Claude borders.
- Keep busy/menu checks, human draft protection and first-in-first-out delivery. These changes do not authorize arbitrary unknown input layouts.

### Native maintenance and compatibility

- Include the separately reviewed PR #384 native maintenance changes: configuration protection, transactional update/rollback support, and terminal compatibility checks. This platform implementation remains isolated from the shared delivery changes.
- Continue to include PR #386's explicit V3 workflow admission checks, already shipped in v8.7.11; ordinary V2 Frontdesk routing remains independent of Planner and activation-style task IDs.

### Upgrade notes

- Update CCB, then safely reopen affected projects to load the new daemon. No project configuration or conversation migration is required. Desktop, npm and Mobile version metadata are synchronized; no new Mobile interface behavior is included.
- A stale lease referencing an existing pending event or ambiguous execution state is intentionally retained for diagnosis. A timeout is not proof that a reply was never delivered.

## 中文

### 回复投递与通信状态

- 包含 PR #395 及审查后的补充修复：回复等待至少五分钟后，可恢复已确认失效的投递租约，并保留原 job 与 attempt；恢复过程不再创建会永久残留的替代排队任务。
- 保留有效租约归属和执行证据。活动任务、待处理事件及状态读取不确定时继续阻止自动干预；仅凭等待时长不会重新发送回复。
- 静默成功任务和 callback 子任务正确显示终态，不再永久显示回复排队。待投递回复在通信列表中单独展示并关联来源任务，列表保留最近 20 条记录。

### 输入框兼容性

- 识别带标题的 Claude 输入边框，以及已知的无淡化样式 Codex 占位文字和状态栏；恢复普通 Claude 边框对尾部空格的兼容。
- 保留忙碌与菜单检查、人工草稿保护和先进先出投递；任意未知输入布局仍不放行。

### 原生维护与兼容性

- 包含单独审查的 PR #384 原生维护改动：配置保护、事务式更新与回滚，以及终端兼容性检查；平台实现与共享投递修复保持隔离。
- 继续包含已在 v8.7.11 发布的 PR #386 显式 V3 工作流准入检查；普通 V2 Frontdesk 路由仍无需 Planner 或激活格式的任务 ID。

### 升级说明

- 更新 CCB 后，在可以安全中断工作时重新打开受影响项目，以加载新版 daemon。无需迁移项目配置或对话。桌面、npm 与 Mobile 版本元数据同步，不包含新的 Mobile 界面行为。
- 若失效租约仍指向已存在的待处理事件，或执行状态不明确，会保留现场供诊断；超时本身不能证明回复从未送达。
