## English

### Repair OMP conversations over CCB Relay

- Bound Linux OMP history pages by conservative serialized bytes, rather than item count alone. Large real sessions no longer exceed the unchanged 512 KiB Relay inner-message limit.
- Oversized turns and user inputs retain an explicit preview and Read original action. Complete projected originals are returned in versioned UTF-8-safe pages of at most 32 KiB; cursors bind project, agent, namespace, session, generation and content hash. No silent truncation or history clearing.
- Return sanitized, correlated Relay payload-limit errors instead of leaving requests to time out. Mobile distinguishes a conversation-load error from explicit native-host unavailability.
- Forward canonical mobile message target `agent` through Relay, retain compatible `agent_name` clients, and reject conflicting identities. OMP session/generation fences remain intact.

### Compatibility and upgrade

- Update both CCB server and Mobile. The app alone cannot repair an old server's oversized responses. Normally restart the Mobile gateway to load server changes; OMP history and active sessions need not be cleared or forcibly restarted.
- Linux-only OMP Collab policy remains unchanged. Mac retains the legacy terminal/native-history route; other Provider routes remain unchanged.
- Official Android APK uses the normal application ID and release signing. The opt-in `.relaytest` Debug application ID is only for parallel-install repair testing.

### Exercised verification

- Android API 35 ran the production encrypted TLS CCB Relay and host connector, production gateway and Flutter repository against a real upstream OMP CollabHost with deterministic model-free outputs.
- Traversed 196 history items over four pages with exact IDs; reconstructed a 987,082-byte original over 31 pages with matching UTF-8 offsets and SHA-256. Send/live-to-durable/tool/model/stale-fence/disconnect/reconnect/background checks passed with no increased Relay cap and no external model calls.
- Flutter full regression: 865 passed, one skipped; static analysis clean. Python Relay/gateway regression: 216 passed. Real current-project history above 3 MiB encoded into an approximately 103 KiB bounded default page.

## 中文

### 修复经 CCB Relay 加载 OMP 对话

- Linux OMP 历史按序列化字节预算分页，不再只限制条数；真实大历史不会超过保持不变的 Relay 512 KiB 内层消息上限。
- 超大回合和用户输入保留明确预览与“阅读原文”。完整投影原文使用不超过 32 KiB 的 UTF-8 安全分页；游标绑定项目、Agent、命名空间、会话、运行代次及内容摘要，不静默截断、不清空历史。
- Relay 回包超限返回脱敏且关联原请求的错误，不再使请求超时。手机区分会话加载失败与明确的原生宿主不可用。
- 修复 Relay 发送目标字段错配：使用手机标准字段 `agent`，兼容原 `agent_name` 调用并拒绝冲突身份；保留 OMP 会话/代次校验。

### 兼容与升级

- CCB 服务器和 Mobile 需要一起更新；仅更新 APK 不能修复旧服务器的大回包。正常重启 Mobile 网关加载补丁即可，不必清空 OMP 历史或强制重启活动会话。
- OMP 新 Collab 仍仅限 Linux；Mac 保留原终端输入与原生历史路由，其他 Provider 路由不变。
- 正式 APK 使用原包名与发布签名；可选 `.relaytest` Debug 包名仅供并装测试。

### 已执行验证

- Android API 35 使用生产 TLS 加密 CCB Relay、主机连接器、网关、Flutter 仓库，以及真实上游 OMP CollabHost；模型输出为确定性无付费夹具。
- 196 条历史跨四页逐 ID 核对；987,082 字节原文跨 31 页还原，UTF-8 偏移与 SHA-256 一致。发送、实时转持久、工具、模型、过期代次拒绝、断线重连、后台暂停通过；未放宽 Relay 上限，未调用外部模型。
- Flutter 全量 865 通过、1 跳过，静态分析无问题；Python Relay/网关 216 通过；当前项目超过 3 MiB 的真实历史被编码为约 103 KiB 的有界默认页。
