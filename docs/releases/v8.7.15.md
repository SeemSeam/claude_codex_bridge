# v8.7.15

## English

### Continuous OMP Mobile conversations

- Refresh the same native session/branch incrementally by stable identity, retaining loaded older pages and disclosure state. Explicit session, generation, namespace or native branch changes invalidate the active projection instead of merging unrelated history.
- Keep every visible assistant text block in native order. Later assistant messages no longer replace earlier prose; reasoning and tool details remain foldable. Explicit ephemeral stream entries are replaced by durable native records without text-based deduplication. Previously loaded inline content remains reachable as a labeled older snapshot when a turn exceeds the inline budget.
- Accept messages while Linux OMP is running into a persisted, bounded FIFO. Show Queued and Needs review separately from execution. Only dispatch when the host is idle, the native editor is empty and no interactive input is required; never steer into the running turn.
- Require ordered native input association and observed start/stop before dispatching the next item. Persist handoff uncertainty before socket writes. Unknown submissions never replay; disconnected, changed-generation or restarted queues are held for review instead of silently resending. Exact input bindings preserve queued-to-native bubble identity after pending bodies are evicted.

### Relay repair and compatibility

- Include the v8.7.14 Relay byte-budget/original-content and canonical message-target repairs. v8.7.14 publication was paused after user feedback; its immutable tag and partial prerelease are retained, not overwritten. Upgrade to v8.7.15 rather than the incomplete prerelease.
- Linux alone enables the OMP Collab route; macOS retains the original OMP terminal/native-history route and other Providers remain unchanged. Update server and app together. Queue runtime changes require normally restarting idle OMP agents when safe; active work is not forcibly interrupted by the release.
- Pending queues are limited to 64 inputs and 1 MiB of bodies, with 256 KiB per input and a 4 MiB owner-only journal. Capacity rejects new submissions rather than deleting unresolved evidence. Upstream prompt admission is not atomic with concurrent desktop interaction; uncertain outcomes remain explicit.

### Exercised verification

- Android API 35 through the real TLS CCB Relay and upstream CollabHost: large history/original reconstruction, live/durable identity, older-page retention, intermediate prose retention, three UI sends while one runs, dispatch order 4→5→6, maximum one active prompt, empty final queue, model controls, stale fences, reconnect and background pause.
- Flutter full regression: 874 passed, one skipped; static analysis clean. Bun queue/model tests: 23 passed. Selected server/Relay regression: 232 passed; actual OMP TUI model/readback/shutdown and upstream CollabHost smoke passed without paid model calls.
- Deterministic model-free fixture results prove transport/UI/state behavior, not external model quality. No new macOS hardware acceptance is claimed.

## 中文

### OMP 手机连续对话

- 同一原生会话/分支按稳定身份增量刷新，保留已加载的旧分页和展开状态。会话、运行代次、命名空间或原生分支变化时明确失效，不拼接无关历史。
- 按原生顺序保留全部可见 assistant 正文，后续回复不再替换前面的说明；推理和工具细节仍可折叠。临时流 entry 由持久原生记录替换，不按文字猜测去重。回合超出内联预算时，已加载内容作为明确标注的旧快照继续可读。
- Linux OMP 运行中接受新输入进入有界持久 FIFO，显示“排队”和“需复核”，不把排队当执行。宿主空闲、桌面编辑器为空且无需交互输入时才逐条派发，不使用 steer 插入当前回合。
- 下一条派发前要求原生输入精确关联及已观察到开始/停稳；写 socket 前持久化未知状态。未知请求不重放；断连、换代和重启后的队列暂停待复核。精确原生绑定使排队泡转原生输入后保持身份，正文回收后也不残留重复泡。

### Relay 修复与兼容

- 包含 v8.7.14 的 Relay 字节预算、原文分页和消息目标字段修复。v8.7.14 因用户反馈暂停发布，已推送标签与部分预发布产物保留不重打，请升级 v8.7.15。
- 新 Collab 仍仅在 Linux 启用；Mac 保留原终端输入/原生历史，其他 Provider 路由不变。服务器和手机应用一起更新；队列运行时需在安全空闲时正常重启 OMP，发布不会强制中断活动任务。
- 待处理最多 64 条、正文共 1 MiB，单条 256 KiB，属主私有队列日志 4 MiB；满额拒绝新请求，不删除未解决证据。上游不能保证派发与并发桌面操作原子，未知结果会明确保留。
