# v8.7.16

## English

### OMP Python ask caller identity

- Include commit `6d3ae4a53`. OMP's Python tool can filter `CCB_*` and `CODEX_*` from subprocess environments while retaining `PI_*`. An `ask` from a shared workspace could therefore be attributed to `user`, leaving its completed reply without an Agent mailbox return.
- Recover the caller only when `PI_CODING_AGENT_DIR` canonically matches the current runtime's exact `agents/<configured-agent>/provider-state/omp/home/.omp/agent` path and the Agent uses OMP. Relocated runtime roots are supported.
- Explicit sender and existing runtime/actor/session identity retain precedence. A supplied invalid runtime path is not overridden. Unmanaged homes, foreign projects, unknown Agents, other providers and escaping symlinks do not acquire an Agent identity.
- Existing jobs are not relabeled or replayed. No Provider authentication, environment allowlist or native installation is changed. This does not repair unrelated human-turn supersession.

### Community and compatibility

- Replace the WeChat group 2 invitation image with the supplied QR, valid until October 29, and refresh all README image cache keys.
- Retain all v8.7.15 incremental conversation and durable FIFO fixes. Update server and Android app together; queue runtime changes still require a normal restart of idle OMP Agents when safe. No active Agent is forcibly restarted by this release.
- Linux OMP Collab and the legacy macOS route retain their existing boundaries. Other Provider routing is unchanged. Windows remains beta.

### Verification scope

- The included fix has recorded failing-before/passing-after regressions and an isolated probe using OMP 18.12.5's real `filterEnv`; see [identity evidence](../plantree/plans/inter-agent-comm-reliability/evidence/omp-python-ask-identity-20261022.md).
- That probe verifies filtered-environment compatibility, not a live model roundtrip. Publication checks are performed separately for this release.
- Release qualification: 253 identity/routing/provider/release regressions passed; `npm pack --dry-run` passed. A fresh filtered-environment subprocess recovered `frontdesk`, preserved explicit sender precedence and rejected an unmanaged home; the actual CLI printed `v8.7.16`. The stored QR matches the supplied image byte-for-byte and was visually checked.

## 中文

### OMP Python ask 调用者身份

- 纳入提交 `6d3ae4a53`。OMP Python 工具可能过滤子进程环境中的 `CCB_*`、`CODEX_*`，但保留 `PI_*`。共享工作区内发起的 `ask` 因此可能被归为 `user`，任务完成后没有 Agent 邮箱接收回执。
- 仅当 `PI_CODING_AGENT_DIR` 的规范路径精确匹配当前运行态的 `agents/<已配置Agent>/provider-state/omp/home/.omp/agent`，且该 Agent 使用 OMP 时恢复调用者；支持迁移后的运行态根目录。
- 显式 sender 和原有 runtime/actor/session 身份优先级不变；已提供但无效的 runtime 路径不会被此回退覆盖。非托管目录、其他项目、未知 Agent、其他 Provider 及逃逸符号链接不会获得 Agent 身份。
- 不重标记或重放历史任务，不修改 Provider 鉴权、环境白名单或原生安装；不声称修复人为回合取代等其他故障。

### 社区与兼容性

- 更新微信技术群 2 的邀请图及所有 README 图片缓存标识；用户提供的新二维码有效期至 10 月 29 日。
- 保留 v8.7.15 的增量对话与持久化 FIFO 修复。服务器和 Android 应用一起更新；此前队列运行时变更仍需在安全空闲时正常重启 OMP Agent，本版不会强制重启活动 Agent。
- Linux OMP Collab、Mac legacy 路由及其他 Provider 的边界保持不变，Windows 仍为 beta。

- 该探针证明过滤后环境兼容性，不代表真实模型往返；本版另行执行发布检查。
