# v8.7.21

Released: 2026-11-02

## English

### Fixes and native Provider support

- Address #401: legacy OpenCode observation no longer opens the Provider database or its WAL index with SQLite. CCB reads query-only private copies of the database and WAL, leaving the live `-shm` untouched. This removes CCB's reported shared-index truncation path; it is not a claim to reproduce every upstream SIGBUS failure.
- Address #402: OpenCode 2.2.x gains opt-in native task admission and completion, qualified against 2.2.4. Tasks bind an exact native session, workspace, input ID and prompt hash. Native `idle` outcomes finish tasks; completed tool steps alone do not. Lost admission responses never trigger replay. Incompatible legacy schemas now fail explicitly before business submission instead of silently waiting for replies.
- OMP tasks use native task ingress and durable reply receipts, with explicit handling for rejected or ambiguous admission. Existing terminal-based interfaces remain available for providers that use them.

### Upgrade and configuration

- Upgrade with `ccb update`, or `npm install -g @seemseam/ccb@8.7.21` for npm-managed installations. Already running processes retain their loaded code; refresh affected agents normally once idle. Do not delete Provider data or replay uncertain tasks as part of this upgrade.
- OpenCode v2 is explicit opt-in: set `CCB_OPENCODE_API_VERSION=2`, `CCB_OPENCODE_API_URL` to an existing loopback HTTP service, and startup arguments `--session ses_...`. An explicit `--server` must match that origin. For Basic authentication, set `CCB_OPENCODE_API_PASSWORD_ENV` to the name of an environment variable containing the existing service password. CCB does not discover credentials, start a global service, or choose the newest session.
- See [OpenCode completion and configuration contract](../opencode-completion-contract.md). Existing mounted agents and Mobile discovery are not automatically migrated. Windows support remains beta.

### Validation and limits

- Source regression: 359 passed, 2 environment-gated skips. Installed preview regression: 223 passed, 2 skips. Actual OpenCode 2.2.4 service testing used the installed CCB with isolated homes and a local simulated model: queued admission, held streaming without premature completion, exact queued-input cancellation and native idle completion passed. OpenCode 1.19.5 native service regression also passed. OMP 18.13.3 native task/reply integration passed in the prerequisite repair.
- The real-service smoke did not use a paid/cloud model or reproduce the reporter's Arch environment. Multi-step tool and malformed-protocol paths have automated contract coverage; production project and Mobile/VM end-to-end retesting is not claimed.
- OpenCode 2.2.x has no atomic active interrupt fenced by expected input ID. CCB cancels exact pending inbox inputs and detects observed delivery races; a 204 is not proof that active work stopped. Active-turn cancellation and restart-time execution observation restore remain unsupported. Streaming previews are best effort.

## 中文

### 修复与原生 Provider 支持

- 处理 #401：旧版 OpenCode 状态读取不再通过 SQLite 打开 Provider 的数据库或 WAL 索引。CCB 对数据库与 WAL 的私有副本执行只读查询，不触碰运行中的 `-shm`，消除报告中 CCB 截断共享索引的路径；不宣称复现了上游所有 SIGBUS 故障。
- 处理 #402：为 OpenCode 2.2.x 增加显式启用的原生任务提交与完成判定，已使用 2.2.4 验证。任务精确绑定原生 session、工作目录、输入 ID 和提示词哈希，由原生 `idle` 结果判定完成，不把工具步骤结束当成整轮结束。准入响应丢失不会触发重放；旧版读取器遇到不兼容表结构时，会在发送业务任务前明确报错，不再静默等待回复。
- OMP 任务改用原生任务入口和持久回复回执，明确处理拒绝或归属不确定的准入。其他依赖终端的 Provider 接口继续可用。

### 升级与配置

- 使用 `ccb update` 升级；npm 安装可执行 `npm install -g @seemseam/ccb@8.7.21`。运行中的进程继续使用已加载代码，请在相关 agent 空闲后正常刷新。本次升级不需要删除 Provider 数据，也不应重放结果不确定的任务。
- OpenCode v2 需要显式启用：设置 `CCB_OPENCODE_API_VERSION=2`，将 `CCB_OPENCODE_API_URL` 指向现有本机回环 HTTP 服务，并通过启动参数指定 `--session ses_...`；显式 `--server` 必须与该地址一致。使用 Basic 鉴权时，将 `CCB_OPENCODE_API_PASSWORD_ENV` 设置为保存现有服务密码的环境变量名。CCB 不自动发现凭据、启动全局服务或选择最新 session。
- 详见 [OpenCode 完成与配置契约](../opencode-completion-contract.md)。已有挂载 agent 和 Mobile 服务发现不会自动迁移；Windows 仍为 beta。

### 验证与限制

- 源码回归 359 项通过、2 项因环境条件跳过；安装预览版回归 223 项通过、2 项跳过。真实 OpenCode 2.2.4 服务测试使用安装后的 CCB、隔离目录和本地模拟模型，验证原生入队、流式输出不提前完成、按精确 ID 取消排队输入及原生 idle 完成；OpenCode 1.19.5 原生服务回归通过。前置修复中 OMP 18.13.3 原生任务与回复集成已通过。
- 真实服务烟测未使用付费或云端模型，也未复现报告者的 Arch 环境。多步工具与异常协议路径由自动化契约测试覆盖，不宣称完成生产项目或 Mobile/虚拟机端到端复测。
- OpenCode 2.2.x 没有按预期输入 ID 原子中断活跃轮次的接口。CCB 取消精确的待处理 inbox 输入，并检测已观察到的投递竞态；204 不代表活跃任务已停止。活跃轮次取消和重启后执行观察恢复暂不支持；流式预览尽力提供。
