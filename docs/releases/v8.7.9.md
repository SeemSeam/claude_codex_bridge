# v8.7.9

Released: 2026-10-10

## English

### Codex ask identity and result delivery

- Fix bare `ask` commands from managed Codex tool shells being recorded as `user` when the native shell policy filters inherited environment. Requests now retain the calling Agent identity so completed child results return to its mailbox (PR #376).
- Apply the current routing identity to both local CLI and managed app-server launches, including resume/fork and startup arguments containing stale caller values. Preserve unrelated shell settings and external Provider configuration.
- Verified with actual Codex → OMP/Demo → Codex and reverse OMP → Codex → OMP roundtrips, plus Claude Sonnet 4.6 → Codex → Claude: one submission, correct result, consumed return and drained queues. Native restrictive shell-policy probes and regression suites also passed.

### Upgrade notes and limitations

- Update CCB, then safely reopen affected projects to load the new daemon and Codex launch arguments. Existing running processes do not acquire the launch fix automatically. No manual project or conversation migration is required.
- Explicit `shell_environment_policy.include_only` restrictions must allow the CCB routing fields; this release does not broaden that policy. The defect reproduces on multiple CCB/Codex versions and is not established as a recent version regression.
- Pi full real roundtrip qualification remains blocked by its configured model service reporting insufficient balance/resources. Default Claude routes rejected unavailable models; the successful real Claude test used `claude-sonnet-4-6`.
- Experimental PR #366 remains excluded. The separate already-pasted-but-unsubmitted symptom in issue #356 remains open. Desktop, npm and mobile version metadata are synchronized; no new mobile interface behavior is included.

## 中文

### Codex ask 身份与结果回投

- 修复 managed Codex 工具 shell 被原生环境策略过滤后，裸 `ask` 被记录为 `user` 的问题。请求现在保留调用 Agent 的身份，使子任务完成后的结果能够回投到其邮箱（PR #376）。
- 本地 CLI 和 managed app-server 启动均应用当前路由身份，覆盖 resume/fork 以及启动参数中的旧调用者值。保留无关 shell 设置与外部 Provider 配置。
- 已通过真实 Codex → OMP/Demo → Codex、反向 OMP → Codex → OMP，以及 Claude Sonnet 4.6 → Codex → Claude 往返：单次发送、正确结果、回投已消费、队列清空。原生限制环境策略探针和回归测试也已通过。

### 升级说明与限制

- 更新 CCB 后，在可以安全中断工作时重新打开受影响项目，使新版 daemon 和 Codex 启动参数生效。已运行进程不会自动获得启动修复。无需手动迁移项目或对话。
- 显式 `shell_environment_policy.include_only` 限制仍需允许 CCB 路由字段；本版不会扩大该策略。问题在多个 CCB/Codex 版本均可复现，尚不能认定为近期版本回归。
- Pi 完整真实往返仍被其模型服务的余额/资源不足阻碍。默认 Claude 路由拒绝不可用模型；通过的真实 Claude 测试使用 `claude-sonnet-4-6`。
- 继续排除实验性 PR #366。Issue #356 中独立的已粘贴但未提交现象仍保持开放。桌面、npm 与手机端版本元数据同步；不包含新的手机界面行为。
