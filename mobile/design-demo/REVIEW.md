# CCB Mobile 交互原型与自审

本目录是独立设计原型，不改变 Flutter 应用，不接真实服务器。
直接打开 index.html，或在本目录启动静态 HTTP 服务即可体验。

## 提供的六个界面

### 双模式增量原型

打开原型默认进入 Agent 对话，顶部可直接切换“对话 / 终端”。
输入区上方“终端现场”默认收起，展开显示最后四行只读快照，可按
“模拟新输出”更新，或一键进入完整终端。不会连接或控制真实进程。
两模式共享目标身份，各自保存目标草稿和滚动位置；模式切换不发送。

浏览器验证：聊天草稿与 120px 滚动位置、终端草稿与 50px 滚动位置
切换后保持；断网时终端控制按钮禁用；320px 宽度两模式无整体横向
溢出。已人工检查展开预览的截图。预览使消息区域缩小，因此推荐
手机默认收起；暂不引入上下各半分屏。网页未模拟原生输入法或实时
ANSI 终端，仍需在真实实现阶段验证键盘避让与终端触控。

项目首页、Agent 会话、全部 Agent、收件箱、设置、终端控制示意。
支持项目/Agent 搜索、项目状态筛选、页面跳转、模拟消息输入、
独立目标草稿、单条通知已读、设置弹层、主题/密度和离线状态预览。
终端按键、配对、模型变更和附件仅演示，不执行真实操作。

## 自审结论

- 推荐保留：项目/收件箱/设置三入口，设置与首次配对分开；会话
  顶部保留目标身份；状态与未读分别表达；详细日志默认折叠可展开。
- 推荐优先试用紧凑密度：舒适版项目卡仍较高；列表内容增加后，
  紧凑版更符合随身快速查看的目标，但触控区域不应随视觉一起缩小。
- “工作中发送”是否允许排队必须服从真实 Provider 能力；原型文字
  表达的是交互意图，不能直接映射成通用后端承诺。
- 任务摘要目前为人工模拟。生产环境只展示有来源的摘要，缺失时
  隐藏；离线时必须明确数据过期，不能保持看似实时的绿色而无说明。
- 全部 Agent 页解决大量标签难找的问题，但当前示例只有四名。
  真正实施前应覆盖 20+ Agent、超长中文名、等待授权状态和断线恢复。
- 自审修正了：重复点击通知重复扣减、通知跳错项目、切换演示场景
  丢草稿，以及主页与收件箱模拟未读总数不一致的问题。
- 原型弹层有关闭按钮、Escape 支持，但未做完整焦点陷阱；生产
  应使用 Flutter 原生 modal/accessibility，不直接复用网页交互代码。
- 此原型不验证 Android 返回手势、后台推送、输入法避让、终端选区
  或真实网络可靠性。颜色之外保留状态文字和图形。

## 用户审查重点

1. 主页“任务信息优先”的层级是否符合实际查看习惯？
2. 舒适/紧凑哪一种更合适，状态颜色是否过弱或过强？
3. 是否接受顶部减少按钮，以“更多”换取清楚的 Agent 身份？
4. 是否需要把“等待处理”独立成入口，或留在收件箱中即可？

验证记录：Chrome 中逐页运行，六个页面在 320px 手机容器的亮色/
暗色两种主题下整体无横向溢出；草稿跨重绘保留、离线发送按钮禁用、
重复打开同一通知只扣减一次的检查通过。1250×1000 桌面预览中主页
与聊天页截图已人工检查。已在 emulator-5554 配置本地 8765 端口转发
并打开 Chrome 原型地址；原生应用未改动。此检查不等于真实手机
键盘、屏幕阅读器或后台生命周期验收。
